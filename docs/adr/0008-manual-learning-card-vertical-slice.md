# Start with an explicit, version-pinned manual learning card

Status: Accepted

The first co-learning implementation uses Ai Notes itself as the only authorized owned project. A GitHub repository URL starts a one-time analysis in the long-lived co-learning conversation. A plain repository URL resolves to the default branch's current commit and records its SHA and verification date; Release, PR, Issue, tag and branch URLs retain their specified target and add only the project context needed to understand it.

The result is one conversation-native learning card covering the project's problem, core abstraction, important architecture or interfaces with official evidence, at most one evidence-gated connection to Ai Notes, non-applicable conditions and risks, and the next explicit feedback action. No valid connection is an acceptable result. Routine cards are not automatically written as knowledge documents; only an explicit user request to preserve a conclusion or a confirmed experiment result authorizes project documentation or an ADR. Skill authoring remains separately controlled.

Before daily automation, ten runs are manually triggered: at least three begin with user-nominated projects and at least three exercise Codex active discovery. A discovery run screens no more than twenty metadata candidates, deeply reads no more than five and reports no more than three connections. At least six runs must receive an explicit positive action and dual-side evidence errors must not exceed one. Silence is never persisted as feedback.

This vertical slice comes before multi-project support, daily scheduling and complete project dossiers. It tests the riskiest product claim—whether a real external project can produce a useful, verifiable connection to the user's current work—without first building a larger collection system.
