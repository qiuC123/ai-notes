# 三榜核对范围调整（2026-10-06）

用户在解释“许可范围仍有漏判”后明确回复：**“这个不需要核对”**。从这次决定起，许可证条款、组件适用范围和商用权限不再作为新任务的评分、内容复核或交付门槛。介绍和评分理由不主动写这些许可结论，仍围绕用途、亮点、已知支持系统和链接发现项目。

## 已落实

- 当前配置使用 `license_review_scope=excluded.v1`，并保存到每个新任务的冻结 policy。原文提取、评分、公开复核及可选逐理由复核沿用该范围，不能临时读取最新配置改旧任务。
- 只适用于当前 public discovery 流程；缺少标记的旧任务保持旧提示、身份和输出形状，未知标记或不支持的流程在调用前拒绝。
- 不深入解释许可证条款，不核对组件归属、商业使用权限，也不因此降低分数或暂缓交付。开源栏目仍可保留原文明确的仓库开源身份或许可名称，不把它扩展成条款、范围或商用结论。
- 用途、功能、支持系统、版本、事件和正文实际描述的免费／收费入口继续依据原文核对。混合句中的许可部分不检查，不代表同句的其他功能事实免检。
- 不删除整句、不用许可关键词过滤整个 defer，也不把历史拒绝改成通过。原始评分、模型响应、独立审计和归档保持。
- 权重、门槛、flags、来源等级与榜单周期数量保持。逐理由 gate 仍为显式选项，自动化仍 PAUSED。

## 验证

验证包括：新范围从冻结 policy 到原文提取／评分／公开及逐理由核对的传递；旧 prompt 和来源请求不接收新规则；保存的非许可事实 defer 不被洗成 accept；混合句其余事实仍受现有 schema/判决约束。测试只使用临时数据库、合成资料和 MockTransport。

完整三榜回归 **564 项通过**（80.765 秒）。最初回归发现旧版测试夹具继承了新范围标记；已在明确模拟旧合同的入口移除该标记，保留原断言与生产验证。最终记录保存在 `work/digest-license-review-scope-20261006/offline-tests.log`，首次失败记录另存。

本轮没有真实模型 API、候选网络采集、正式榜单或生产调度；规则实现不等于已经证明模型稳定遵守新范围或完成代表性评分校准。

## 后续重点

用未见过的候选资料检查“用途、亮点、支持系统”的介绍和筛选价值，不再专门回归 Czkawka 的许可范围。旧错例记录作为当时采用范围下的历史结果保留；新的核对范围以本文件及当前冻结配置为准。
