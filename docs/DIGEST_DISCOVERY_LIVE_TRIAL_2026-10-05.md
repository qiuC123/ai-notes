## 对发现目标的影响与下一组工作

1. **补对原文，而非补长介绍。**读到模板或开发 README 时，优先去真实产品官网／用户文档；官方仓库 metadata 若被用于介绍，必须明确其来源、时间和范围，不能绑定到不含该功能的 README。绑定引文有缺口不等于功能错误。
2. **复核应分清公开文字与内部材料。**实际展示的标题、用途、亮点和系统要核对；内部背景字段发现问题需要保留、修正，但不应单凭它否定已有原文支持的公开用途或混合许可的开源身份。只有问题实质影响公开介绍或入选依据时，才决定暂缓。
3. **处理无效引用生成。**TagSpaces 失败是模型输出引用 ID 无效，不是介绍不完整。后续改进应针对合法 ID 选择及结构，不用人工修回执后冒充模型成功。

上述是此次试验定位到的修正方向，**本轮未实施代码修正、再跑模型或补采**。权重、65/45 门槛和来源等级没有改变。未收到新的读者选择标签，不因两项分数声称标准已校准；新闻／游戏栏目质量也没有在这批项目试验中验证。
