# 三榜筛选修正：产品原文与公开介绍范围

2026-10-05。用户确认后完成 v12 本地修正。仍采用名称、用途、亮点、已知支持系统和链接的发现式介绍；数值权重、65／45 门槛、限分、八栏目、历史去重和来源等级保持。自动化继续 PAUSED。

## 本次改变

| 环节 | 修正后的行为 | 保持的边界 |
| --- | --- | --- |
| 初筛 | 仓库简介中有清晰用途时，可进入原文深核；版本和安装资料尚未读取不自动构成初筛拒绝理由。 | 简介只是发现线索，不算已经核验；原有读者排除条件仍生效。 |
| 产品阅读 | 模板／简短开发说明优先选择仓库内用户文档，根许可证优先；必要时读取仓库声明的主页一页。 | 只使用实际目录或声明入口，不猜路径、不自动更换 fork、不递归抓站；供文仍受总文档数、字符数和补充请求预算约束。 |
| 仓库 metadata | 将已经取得的原始 GitHub JSON 中名称、简介、主页字段作为单独资料，保留 API URL、字节哈希、抓取时间和确切范围。 | 是当前作者自述，不是独立实测或历史版本证据；`commit_sha=null`。指定 release／commit 的阅读不混入当前简介或主页。 |
| 内容复核 | 输入实际展示的标题、用途、系统等公开字段，以及实质评分理由；保留全部供文与逐资料范围。 | 未展示的条件、许可解释、内部理解卡不单独决定刊用；若影响公开文字或评分理由，仍须检查。 |
| 周榜重点 | 先评分排序，再确定当前可入选非阅读重点的展开文字，随后进行该条的一次内容复核。前项暂缓时下一项补位。 | 每条最多一次模型内容复核；展开文字的阅读范围也先机械检查，不能绕过最终公开范围。月榜保留理由、更新说明、新闻日期、阅读作者日期同样进入实际公开字段。 |
| 引用 ID | 新核验请求把允许的段落 ID 写在每个证据数组旁，并明确要求逐字复制；未知 input／output 的证据容量仍为零。 | 只是生成指导，不能保证模型遵从；坏 ID 继续拒绝，不修补原始响应、不付费重试。 |

两项新合同 `source_reading_contract=discovery-reading.v1`、`editorial_scope=public-introduction.v1` 随新初筛冻结。旧任务不自动升级；旧 prompt、评分投影、内容复核输入、请求身份和原始回执继续使用其保存版本。
