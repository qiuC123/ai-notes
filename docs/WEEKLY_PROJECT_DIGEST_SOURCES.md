同一宿主平台内也要区分发布者：GitHub 作者仓库是项目原文，GitHub Trending 是发现榜单；Steam 商店描述来自开发商，Steam 评论来自用户；Hugging Face 模型卡是作者陈述，不是独立评测。

博客、帖子与访谈作为精选内容时，推荐的是文章或谈话本身的阅读价值；作为项目证据时，归入对应项目的来源。聚合站转述先回到原文，访谈和个人复盘中的收入、效果等陈述仍按作者自述标注。

上述是三榜输出分类，不直接沿用采集配置的 `category` 字段。成品应用的内容与同一项目独立提供的开发 SDK，按本次介绍的具体交付物归类，每个条目只进入一个主栏目。

## 3. 用户反馈与开发机会

开发机会是独立的观察部分，不另算项目类型，可来自任何栏目。优先读 GitHub Issues / Discussions、HN 评论、Reddit r/SaaS / r/SideProject / r/webgames / r/gamedev、Steam 玩家评论，以及 Product Hunt 讨论。Reddit 目前仅有按需搜索线索，不宣称授权 API 或浏览器登录渠道已接通。

Acquire.com 是前期讨论过的产品交易线索平台，可作为付费线索备选；本轮未核验访问和列表内容，没有接入，卖方收入陈述不能直接当审计收入。

每条机会必须交代：问题与人群、用户原文及日期、已有方案、是否已修复 / 已实现、可以验证的小切口、未知项。模型生成的主意不能冒充用户需求。

## 4. 三榜的共同边界

- AI 工具的新发现与重要更新按主要用途分别归入 AI 应用、Agent 框架与编排、MCP 服务与连接器、模型与运行工具；CLI / API / 自托管 / 平台等作标签，CLI 不局限于 AI。
- Agent 框架与编排保留独立栏目；允许追踪同一框架新的实质变化，但同级不得重复报道同一更新，也不为填栏目报道普通小版本。跨级可入选，介绍深度按对应榜单调整。
- 游戏独立成栏，可收闭源玩法观察，但必须注明非开源 / 未核实；一般开源项目栏仍需核对源码和许可证。
- 不把不同站点转述的同一公告计算为多条独立证据；按规范项目地址归并候选，结合真实发布／更新事件检查所有已交付同级历史。多一个转述链接不等于新的重要更新。
- 模型、框架、标准只写对具体使用有意义的变化；arXiv 论文默认不进主刊。
- Exa / Jina 是采集工具，Pi 是分析组件，飞书 / Codex 是输出入口，都不是原始内容来源。
- 每天北京时间 19:00 最多记录 20 个新候选或实质更新，保存实际访问来源及失败；次日 09:00 开始日榜、下周一 10:00 开始周榜、次月 1 日 11:00 开始月榜。初筛／深核预算分别为 30 / 12、80 / 35、150 / 60，每次最多补采 20 个，共享当次预算。交付保留原周报任务，不为每个栏目凑数，不代表本表所有平台已接通，也不改变其他采集器的独立上限。
- 延期月榜补采保持原月归属，允许晚核验与有原月发布／重要更新证据的补录；次月首次发现且没有原月新事件的旧项目进入次月候选，不倒填原月。月榜不足 20 条保留草稿，每天有界重试，相同缺口保持安静。
