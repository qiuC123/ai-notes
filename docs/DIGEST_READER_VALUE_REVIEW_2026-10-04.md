# v7 读者价值、内容复核与真实独立执行验收

日期：2026-10-04；改动基线 `ceff990`。这是本轮实现和实验记录，不能替代整个优化计划的验收。当前自动化保持 PAUSED，生产库和旧试验不改写。

## 改动及原因

- 评分明确日榜的介绍价值、周月榜的保留价值；普通实用工具不因非 AI 身份被扣分。当前配置 `v7-reader-value-review-uncalibrated`，权重、限分与门槛保持。
- 新原文合同 `passages.reviewed.v1` 要求简明介绍真实可用路径、保留重要冲突，不将原文片段称为全文或软件实测。旧 `passages.v1` / `claims.scope.v1` / 无标记任务沿用原提取合同。
- 评分后一次 `source-score.v1` 内容复核，同时检查事实各字段、评分理由与本次全部来源片段。发现重要错误或坏结构时暂缓；不改原文、不修分数、不重抽。请求前保存完整输入，响应先入账再校验；旧准备包未启用则不增加调用。
- `scoring_projection=source-refs.v1` 将重复引文换成可逆区间，全文片段只在 evidence_context 提供一次；冻结卡片和服务器端 quote 校验不改。旧无标记投影保留完全相同的值和指纹。
- 真实 worker 暴露输入上限问题后，增加 `InputBudgetExceeded`：原文、评分、复核单条超出 60,000 字符时保留材料暂缓，继续本期其他候选，不提高限额或随意切掉内容。通过 `python -m` 执行时统一异常模块身份，保留可安全展示的错误及 waiting_input 状态；GitHub 大小写仓库地址正确进入固定提交 README 读取。

API 预算仍为 `1 + 3 × 深核上限`。内容复核使用既有第三次请求余量，不增加循环。预算、证据和周期准入不会被分数或复核 accept 越过。

## 真实隔离 worker

在新沙箱中用 SQLite backup API 保留生产全部观察和 22 期历史，真实时间运行到期的 `daily:2026-10-03`，未伪造 discovered_at 或 --now。没有在生产启动 schedule/work。

- moral.games：65 分入选，核对正文核心玩法、限制、许可未知、首次发现、真实核验时间及全部同级历史后，可作为一条未试玩的隔离试刊展示。目标至少五条，实际缺四条；只有游戏栏目，不能称完整达标日榜。

- Parrot：冻结的原文输入超过上限，在发送核验 HTTP 前暂缓。保留第一次整期失败及修正后的恢复记录，没有重新初筛、缩短旧冻结输入或补抽。
