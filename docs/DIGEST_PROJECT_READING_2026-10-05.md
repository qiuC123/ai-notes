# v10：项目阅读与证据事实卡

本组把项目阅读方法接入三榜后台。配置为 `v10-project-reading-uncalibrated`，五维评分、权重、门槛和三榜规则保持；生产自动化继续暂停。工具与结构校验不等于理解正确。

## 阅读方法如何进入程序

[项目 Skill](../.agents/skills/digest-project-reading/SKILL.md)保存人工／Codex 阅读方法；Python 后台通过 `digest_reading`、`digest_understanding`、评分投影和文案复核实现对应行为。仅安装 Skill 不会让 API 自动加载它。

仓库读取以问题选择文件：README、实际许可证、安装入口和使用指南；所有文件固定同一 commit。明确更新事件的 release tag／commit 会传给读取器，避免旧事件混入当前默认分支文档。没有全仓下载或运行候选代码。每次最多四份文档、14,000 个供应字符；README 之后的目录及补充文档请求最多六次。文件失败、目录截断和工具缺失保留实际状态。

Gitingest 0.3.1 是可选依赖，已安装到本项目虚拟环境。它只整理已取回的文件；真实原文及抓取回执仍是事实依据。使用独立 Python 子进程隔离其日志副作用，30 秒超时；打包失败不丢弃原文。

```powershell
.venv/Scripts/python.exe -X utf8 -m ai_notes.digest_reading --root . --url https://github.com/owner/repo --max-documents 4 --max-chars 14000
```

## 事实、条件与阅读范围

新 `project-reading.v1` 合同要求模型给出用途、输入、操作、输出、条件与未知项。已知项绑定实际原文段落；程序保存出处、原文引用和标题路径。条件明确区分必需、可选、兼容、可用性和收费，并说明影响的对象。

每份资料带 `digest-source-scope.v1`：供应字符范围、原文字符数、哈希、文件路径、commit、读取方式，以及完整捕获文本／摘录／未知。范围与引文由程序生成，模型不能补写。完整捕获文本也不代表读过整仓或完成软件实测。

评分和复核复用同一事实卡、原文与范围；评分输入把引文转为可还原的原文位置，避免重复堆叠。不同候选即使共享同一事件 URL，也使用各自冻结资料，不能混入对方的正文。已知摘录上的明确全文断言会在评分前暂缓，原始坏回执保留。

程序能验证绑定、范围与部分明确断言，不能证明全部语义。输入输出方向、最低依赖与兼容修复、促销范围仍须核对原文。复核与提取使用同一模型，不算独立人工证据。

## 恢复与旧任务

新任务在请求前冻结资料、范围、策略和提示词。响应保存后发生中断，恢复直接复用，不能重新抓取后形成另一笔请求。旧 screen／preparation 保持原合同、原输入与原分数；缺少权威快照的旧任务停止，不能套用当前规则。生产历史与凭据不进入本次试验。
