## 已确认方向（2026-10-04）

1. 日报以有实际影响的 AI 动态、产品更新和少量可直接使用的工具为主，不把每天发现不同的开源项目当成硬任务；周/月集中筛选值得保留的项目和用法。
2. 工具评价增加读者适配与使用验证：明确是否需写代码、硬件或复杂部署；结合维护、发布、第三方使用反馈/案例、下载与关注量，不只读作者 README。
3. 低 Star 且缺少独立使用证据的项目先观察，有具体场景、可用成品和真实反馈的成熟旧项目也可作为首次推荐。
4. 新闻与项目分开判断：新闻看事件影响、变化与原始出处，工具看用途、门槛和成熟度。不要用新闻凑项目数量，不将论文、融资等内容自动设为重点。

### 实施口径

- 这是编辑方向，不设固定新闻/工具比例，不增加“每日新项目”指标。日榜 5～8、周榜 20～25、月榜至少 20 条保持；新闻计入精选总条数，正文明确标为新闻，不冒充项目条数。不足时沿用现有交付/草稿规则。
- 八个主题栏目保留；`news` 是与 `project`、`update`、`reading` 并列的内容类型。模型公告归模型与运行工具，产品变化归 AI 应用；确实影响普通读者的行业动态可归博客、帖子与访谈。融资、论文、公司宣传不因热度自动入选。
- 新闻写“发生了什么 → 影响谁 → 应关注或采取什么行动”，核对原始事件 URL 与日期，不套用安装、开源许可证或工具成熟度要求。已发生的公告可报道，未来效果仍明确为计划；不以“能安装”作为新闻资格。
- 新闻按事件所属自然期处理；同一原始事件 URL 在同级只能报道一次，改为项目更新或更换候选 URL 不能绕过。旧新闻不靠新发现时间进入今日日榜；原期事件可以凭原文证据用于原期补采，保留实际采集时间。目前事件字段要求带时区时间戳，无法从原始材料确认时间的新闻先暂缓，不伪造零点或拿 RSS 刷新日期替代。
- 工具优先直接可用；纯编译测试、CI、代码内部维护工作流和实际树莓派硬件不作为推荐方向。CLI/MCP/Skills 仍可收录能借助现成助手完成实际任务的用法，不按名称误排 Pi 软件。
- 不适合当前读者或缺少具体操作/演示/使用依据时暂缓；作者演示、作者自述、独立反馈、实际测试分别标明。没有统一 Star 门槛，高星不免核验、低星不自动淘汰；周月声称成熟、稳定时需要对应依据。
- 新策略 `v2-reader-fit-uncalibrated` 增加独立新闻权重和读者/使用证据限分标记；冻结 v1 对比结果不回写、不重算成新规则结果。真实效果待新样本验证，本轮未调用付费模型。
- 独立采集配置加入 OpenAI News、Google AI 两个官方 RSS，与现有 Show HN/HF 共享每日最多 20 个新候选的预算。AIHOT 保留参考及聚合发现定位，不把其线上接口当成已接入。RSS 只保存 discovered 线索，订阅日期不等于核验完成。

代码、测试、规则变更不等于已恢复运行或已产出新版真实日报。当前自动化保持 PAUSED，生产候选库和既有文章保留。
