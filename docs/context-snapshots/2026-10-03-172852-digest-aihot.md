## 1. 要解决什么问题

用户想持续发现有用、有趣、适合上手的开源项目和工具，产出日榜、周榜、月榜，也兼顾少量有证据的开发机会。热度用于发现线索，入选优先看实际价值、适用读者和可核验程度。用户希望先借鉴 AIHOT 改善采集与筛选，再把成熟流程部署云端，减少对个人电脑和长篇 Codex 对话的依赖。

仓库还包含项目共学、关联发现实验、飞书入口、Pi 接入和旧 Release 管道。**本次优化范围是三榜系统，不能把其他模块一并重写，也不能把旧 Release 采集器当作三榜已经自动采集的证明。** 仓库内 `src/aihot/` 是本项目的旧管道命名空间，不是上游 `KKKKhazix/AIHOT` 的源码副本。

## 2. 当前真实架构

```text
本地 Codex heartbeat（北京时间 09 / 10 / 11 / 19 点）
  → ai_notes.digest dispatch：按当前真实时间返回本次动作
  → Codex 会话：读取规则、检索发现、阅读原文、筛选、核验和写作
  → digest-batch.v2 → ingest → SQLite 批次与观察记录
  → digest-issue.v2 → render / draft → archive
  → SQLite 归档账本 + Markdown 正文 + JSON 清单 + 本地历史索引
  → 原 Codex 对话交付；普通候选积累保持安静
```

项目版本为 `0.3.0`，Python 要求 `>=3.11`。三榜入口是 `python -m ai_notes.digest`，核心见 [`src/ai_notes/digest.py`](https://github.com/qiuC123/ai-notes/blob/9d139763b2d6532df5020279e4b8cac08694564b/src/ai_notes/digest.py)，测试见 [`tests/test_digest.py`](https://github.com/qiuC123/ai-notes/blob/9d139763b2d6532df5020279e4b8cac08694564b/tests/test_digest.py)。

三榜 CLI 已承担确定性工作：批次幂等入库、URL 归一化、观察记录、时间归属、同级历史去重、核验字段一致性、草稿、归档和导出恢复。它**不负责联网搜索、模型调用、事实真伪判断、消息发送或发布**；`dispatch` 返回动作，不是后台任务执行器。当前没有独立于 Codex 会话的三榜采集与成文 worker。

持久化位置为 `data/weekly_digest/digest.sqlite3`，文章和清单在 `outputs/digest/`。这些目录被 Git 忽略。核心按项目根目录定位文件，不能简单判断为只能运行在 Windows；但现有调度、工具环境和交付依赖本地 Codex，尚未验证 Linux 或云端无人值守运行。

## 4. 已确认规则，规划时应保留

### 栏目与编辑定位

八个主栏目：**开源项目、Skills、AI 应用、Agent 框架与编排、MCP 服务与连接器、模型与运行工具、游戏、博客/帖子/访谈**。每项一个主栏目，空栏目省略。CLI、平台、自托管等作为标签，不再按编程语言分栏目。实用开源内容占主要篇幅；值得学习或有趣的项目也可入选，不能只按用户已经在用的工具决定是否推荐。

开发机会最多 2 条，必须有用户问题原文和现有方案核对，不计入精选条数。文档声称、演示展示、实际测试必须区分。

### 三榜与采集

| 流程 | 北京时间 / 统计周期 | 数量与预算 |
|---|---|---|
| 候选积累 | 每天 19:00；通常回看 48 小时，失败后最多补查 7 天 | 最多 20 个有理由的新候选或重要更新，不设最低数 |
| 日榜 | 次日 09:00；前一自然日 | 目标 5–8；初筛最多 30，深核最多 12 |
| 周榜 | 周一 10:00；上个完整周一至周日 | 目标 20–25；通常 3 个非阅读重点，不足时取实际数；初筛 80，深核 35 |
| 月榜 | 每月 1 日 11:00；上个自然月 | 至少 20；初筛 150，深核 60 |

各榜必要时补采最多 20 条，并共用筛选预算。共享候选库，各期独立筛选，不能只按日榜晋升周榜、周榜拼成月榜。日榜、周榜不足目标时可交付实际非空结果并解释缺口；零条保留草稿。月榜不足 20 必须保留原月草稿，在后续候选任务中有界重试最早的一期。

跨级可重复，但要增加阅读价值；同级默认不重推，只有真实且尚未报道的重要更新可再次入选。必须检查全部已归档同级历史，包括期号更晚但先交付的文章。已归档同一期不覆写、不重复通知。

首次正式归档时，`prepared_at` 和各条 `verified_at` 距真实执行时间均须在 24 小时内；过期要重新核验，不能只改时间戳。已有同输入归档的幂等重放另按恢复导出规则处理。

延期月稿只能使用月末前已发现候选，或有原月正式发布/重要更新原文证据的期后补采。次月新发现的旧项目、次月发生的新更新不能倒填。首次发现、原始事件日期、实际抓取和核验时间应分开记录，首次发布日期未知就保留未知。

### 来源政策

Show HN、搜索、榜单与聚合站用于发现；入选关键主张回到仓库、官网、作者原文或原始访谈核验。Hugging Face 已作为直接来源，涵盖 Models、Spaces、Blog 的轮换计划；配置为来源不等于每类均已验证稳定采集。

轮换计划通常以 Show HN 为基础来源；周一 GitHub Trending，周二 Skills/MCP，周三 AI 应用/HF Spaces，周四框架/HF Models，周五阮一峰周刊/HF Blog，周六游戏，周日补齐栏目。聚合平台单独管理，不作为事实权威。

**HelloGitHub 自 2026-09-15 起不再作为候选来源，不抓新旧月刊、不从历史精选补数；只借鉴有趣、入门级、便于理解的编辑定位。** 仓库里保留的历史记录不改变这条政策。旧管道的 12 个 `trial` Release 源也不代表三榜已覆盖全部上述来源。

## 5. AIHOT 能提供什么参考

以下“已核对”仅指固定版本的代码/文档，不代表在本机验证过运行效果。

| 方面 | AIHOT 已核对的设计 | 对本项目的规划建议，尚未实施 |
|---|---|---|
| 采集与执行 | 多类 reader、API/worker/web 分离、PostgreSQL 与 pg-boss 队列 | 借鉴来源适配器、任务状态和失败恢复，先评估现有 Python 中可做的最小改动 |
| 筛选 | 先过滤，再用同一模型/提示独立打分两次并取平均；来源层级阈值 | 借鉴分阶段筛选和稳定性评测；不能把两次调用说成两个模型独立交叉验证 |
| 评价目标 | 按内容类型分配维度权重，最终输出关注度分数 | 改为项目实用性、适用读者、证据与上手条件；不直接复制新闻关注度阈值 |
| 评分解释 | 多个维度在提示词里计算，主要输出最终 `attentionScore` | 若要排查误选，需要设计可保存的入选/排除理由及证据，而不是宣称上游已有完整可审计理由 |
| 质量评测 | 标注集、开发/留出集、precision/recall 与阈值扫描 | 用用户偏好的样本做小规模基线，再决定是否需要复杂评分与更多模型调用 |
| 去重与事件 | 语义召回、事件关系判断、来源数和时间衰减热度 | 区分“项目身份”与“具体更新事件”；转发同一消息不能算多份独立证据 |
| 成本与呈现 | worker 调模型，页面读取结果；请求记录、复用、预算；Web/RSS/API/MCP | 借鉴预生成结果、预算和复用；先明确是否需要完整公开站点或仅个人管理页 |
| 云部署 | Docker Compose，API/worker/web 与数据库服务 | 当作部署参考，不据此预设全量 TypeScript 重写或立即迁移 PostgreSQL |

## 6. 需要规划解决的缺口

1. **执行独立性。** 把代码上传 GitHub 不会产生采集 worker；把现有 CLI 放服务器上，也不会自动替代 Codex 承担的检索、核验和写作。
2. **候选召回。** 当前 `candidates` 先按规范 URL 排序再按 `limit` 截断。池子扩大后可能影响未入选候选被审阅的机会；这是静态代码发现的风险，尚没有漏选率测量。
3. **选题质量。** 已有记录和校验，但还没有用户标注基线，无法量化“现在入选不理想”的原因或证明借鉴后更好。数量达标不等于选得好。
4. **调度恢复。** 现有 `dispatch` 是分流器，缺少独立执行器、任务租约和崩溃恢复；当前到期视图不能代替全部历史缺期检查。具体补期策略需要明确，不能自动把旧内容倒填。
5. **云端准备。** 运行数据、归档、配置和密钥需要迁移方案；现有公开仓库不带本机数据库。需定义迁移校验、备份恢复、调度切换与重复通知防护。

建议比较三条路径：继续扩展现有 Python；抽取 AIHOT 的机制/少量组件；直接 fork AIHOT 后适配业务。以现有数据和规则保留、维护成本、模型调用成本、稳定性及个人使用复杂度决定，不预设选哪一条。

Dot 如参与，先当作协调与查看结果的入口候选。规划前需要核对官方当前的持续运行、调度、连接电脑和额度边界；不能把“对话不计某项额度”推导成无限免费模型任务或通用服务器托管。目标云平台、预算、公开访问范围尚未确定。
